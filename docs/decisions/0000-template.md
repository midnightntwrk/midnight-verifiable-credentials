# ADR-0000: Decision title

- Status: Proposed
- Date: YYYY-MM-DD
- Owners: package or subsystem owners
- Supersedes: none

## Context

Describe the problem, constraints, and evidence that make a durable decision
necessary.

## Decision

State the decision in terms that can be tested during implementation review.

## Consequences

Describe intended benefits, accepted costs, and operational or security risks.

## Rejected alternatives

Record credible alternatives and why they were not selected.

## Follow-up

Link implementation work to the canonical backlog or a narrower plan. Do not
turn the ADR itself into an execution queue.
